## 1. 本章要解决的问题

微盘轮动（S13 回测的主角）每天的第一步是"选出今天的池子"：流通市值最小的 N 只，但把死穴剔干净。这一步是**纯数据面的活**——确定性、可对拍、跟 LLM 无关。S12 把它做成纯函数 + 只读工具；S13 的按日重放引擎直接消费同一函数（选股规则逐日重放 = pickPool 对历史快照逐日调用）。

## 2. 设计讲解

### 2.1 七道过滤的口径与文章依据

过滤次序固定（便宜的在前、排序最后）：

| # | 过滤 | 默认阈值 | 依据 |
|---|---|---|---|
| ① | 停牌/无效行 | price ≤ 0 | screenQuotes 同款隐式闸 |
| ② | ST/退 + 北交所 | isExcludedStock | **用户红线**（trading-rules.md 1-2/1-3，非文章口径） |
| ③ | 流动性 | 日成交额 ≥ 3,000 万 | 文章三大死穴之流动性 |
| ④ | 低价 | 股价 ≥ 2 元 | 面值退市死穴 |
| ⑤ | PE 区间 | 0 < PE ≤ 300 | 亏损剔除 + 爆表剔除；**未知 PE 剔除（保守）** |
| ⑥ | PB > 0 | pb > 0 | 负净资产剔除 |
| ⑦ | 次新 | 上市 ≥ 365 天；缺 IPO 表退化 N/C 前缀 | 波动无参考 + 解禁压力 |

所有阈值进 `PickPoolFilter` 可调——默认值是**保守起点不是权威口径**（trading-rules.md 的出场/仓位节还空着，池参数属同一性质：调试期实跑后由用户定稿）。"板块"过滤的实现口径 = 北交所红线剔除；创业板/科创板**在池内**（本章候选 20 只里 sz301xxx 占 9 席）——文章口径若要剔创/科，调试期加开关，记挂账。

### 2.2 IPO 日期源：真机调研结论（本章的调研交付）

- **东财 clist f26 = 上市日期**（YYYYMMDD 整数），轻字段（f12,f13,f26）全市场分页 ~60 页。**2026-10-21 真机实测：Node fetch 可达**（5,922 只/0.7s），2026-10-18 记档的 WAF RST **不复现**——记档更新：东财备源对 Node 的可用性是**时变的**，每次依赖前先探。fixture 照录：`{"f12":"003816","f14":"中国广核","f26":20190826}`。
- 落地形态：`QuoteSource.fetchIpoDays?` **可选能力**——新浪列表无此字段（主源不实现），东财备源实现；`get_stock_pool` 调用失败/缺能力时**退化 N/C 前缀过滤**（首日 + 上市 2-5 日）并在输出注记里明说（"IPO源东财f26 5922 只" vs "退化N/C前缀"）——数据源降级在产品面可见，不静默。
- 单票 stock/get 接口不支持 f26（只有 clist 带）——探测时顺带记档。

### 2.3 纯函数与工具的分工

`pickPool(quotes, filter)` 是纯函数（today 由参数注入保确定——S13 回测逐日重放时传历史日），工具只做装配：取快照（ensureFresh 15s）→ 取 IPO 表（try/catch 退化）→ 调纯函数 → 格式化输出（候选数/全市场数/IPO 源注记 + 流通市值升序名单）。**输出是候选名单不是买点**——研究面工具，描述里写死。

## 3. 翻车记档

- `group.map(emFetchPage)` 把数组 index 传进了 `fields?: string` 参数——给回调加可选参数时，直接引用函数名当 map 回调是隐雷（签名兼容性 TS 会查参数逆变，撞上 optional string/number 才炸）。包一层箭头函数。
- 调研推翻记档要留痕：东财 WAF RST 是 2026-10-18 的观察，不是永真——**记档类知识自带时效**，这次是好方向（阻塞变通途），反向时变更要警惕（新浪主源哪天掐了也一样）。
