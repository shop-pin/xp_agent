## 1. 本章要解决的问题

S10 结束时系统看价格不看盘口：挂单墙（托单/压单）是 A 股最常见的手法，价格没动而买五档堆了三倍量——这类信息 LLM 裁决时完全看不见。S11 把盘口接进来，但**只接免费的**：新浪 hq 明细接口本来就带五档量价，parser 一直在调这个接口只是没解析这些字段——增量是解析不是新源（第五批需求判定 ② 的原话）。

## 2. 设计讲解

### 2.1 范围纪律先于实现（决策 #9）

五档盘口**只进关注面**（watchlist ∪ 持仓 ∪ 信号股，S10 的宇宙三腿），全市场轮询仍然只有成交快照；L2/逐笔付费数据不接。这条纪律决定了数据的流向：

```
data-store 10s 心跳（已有）→ universeCodes().slice(0,50) → detailQuotes（hq 批量）
    → ctx.emit("market/book", {at, books})      ← 引擎盘口缓存的口粮
    → 盘口行追加 watch-detail/<day>.jsonl        ← 盘口是明细层的一部分（plan 原文）
```

轮询的宿主选了 data-store 而不是 market-data：**宇宙的定义方在 data-store**（三腿并集），market-data 保持纯数据面（解析+取数+工具），不知道"谁值得看"。事件把两边解耦——引擎订阅 market/book 自持缓存，规则评估时 `RuleContext.book` 可选注入，非关注面码 book 为 undefined、盘口类规则判 null 自行让路。

### 2.2 两条新规则的机械门槛（Day 1 纪律的延续）

- **book-pressure**：`|压力| ≥ 0.6` **且与 5min 涨速同向** **且 `|chg| ≥ 1`**——三条腿缺一不可。单看压力比值会被主动做出来（价格没动的挂单墙是托单压单把戏）；压力与价格反向时更不能当顺势信号。
- **volume-divergence（量价背离）**：价走出 ±1.5% 而量率 < 0.8 倍——上涨无量=顶背离（信号方向 down），下跌无量=底背离（up）。**方向取背离语义**：这个规则的输出是警示，裁决技能里对应加了"顶背离的 up 追价、底背离的 down 杀跌都要降信心"。strength 沿用带符号涨速（与 rapid-move/breakout down 同约定）。

两条规则走的是 S5 引擎的既有机器（宇宙闸/冷却/重发纪律/fireStats），零新机制——这是把门槛做进规则注册表的复利。

### 2.3 量纲记档

盘口量 = 股（新浪原生），成交量为手（÷100 换算）——**不一致是有意的**：压力是比值量纲自消，盘口行原样落盘保留溯源能力；明细层盘口行 `{at, code, bid[], ask[]}` 与行情行 `{at, code, p, …}` 交错同文件（自描述 JSONL，S13 读侧按字段区分）。

## 3. 翻车记档

- **测试序列的手算错误被实现逮住**：背离用例的量序列写错（循环退出后的 v 又 +40，实际末量 1640 非 1580），surge 手算 0.69 实跑 1.5625——`volumeSurge` 实现是对的（S5 起被多组手算钉死），先怀疑实现的侦察方向错了。教训同 S5：数字对不上先查自己的推导，再看代码。
- **mock verify 期望串写成"单档形"**：get_quote 实际输出是五档斜杠连接的全串，verify 只匹配了第一档——锚文本要锚真实产出的形状，不是脑补的形状（S4 泛锚教训的镜像面：锚太松假阳，锚太理想假阴）。
