# 滑点双补丁：模拟盘成交建模修复（挂账#1，2026-10-31）

模拟盘最大的建模谎言清除：**成交价 = 委托价**。旧模型下 LLM 挂 10.5 买（市价已 10.4）会成交在 10.5——比市价还差的价格照单全收，回测/复盘的数字系统性乐观。挂账 10 天（10-21 建单），一直没做是怕波及面，做完发现波及面本身就是证据。

## 设计（两补丁各管一半）

**① 滑点成交**：`fill = min(委托价, 最新快照×(1+slip))`（buy；sell 对称 `max`）。
- 语义：限价单不可能成交在劣于委托价的价格（A 股限价单真实语义），也**不该成交在劣于市价±冲击的价格**——委托价是"最差可接受价"，不是成交价。
- 委托价贴近市价（漂移内）时 min/max 自然保留委托价 → **现有正常场景数字零漂移**；只有追价单（委托价优于市价）才落进滑点价——治的正是乐观偏差。
- 成交价到分（round2，A 股步长 0.01）；费用/现金按滑点后成交额。

**② 价格漂移拒单**：委托价与下单时刻最新快照偏离 >1% → 拒（fail-closed）。
- 防的是另一件事：ensureFresh 只保快照 15s 新鲜，LLM 从更老的上下文抄价挂单——市价已走、委托价还在原地。拒单文案直接教正确动作："刷新行情后按最新价附近重新委托"。
- 边界取 `> 1%`（恰好 1% 放行）；停牌/无效快照（price ≤ 0）自然落进漂移校验 = 拒，fail-closed 同族。

**滑点配置单源**：`PaperConfig.slippage` 缺省走 `strategy.backtest.slippage`（0.002）——S14 "同一策略配置产出一致行为"锚的延伸：回测的乐观偏差修正与模拟盘同一参数。直 `new PaperBroker` 不经插件的不带滑点（测试直构造向后兼容）。

## 波及面 = 补丁价值的证明

7 个既有测试场景红——全是**借 stale 漏洞的场景**：卖单委托价离快照价 10%（buy@10 后直接 sell@11，快照从没刷过）。真实流程里 LLM 挂卖单前会看到 9.5/11 的行情。修法统一为"卖前把快照刷到目标价"（s7×3 / s8×2 / s9×1 / s10×1 / mock ch39×1）——测试本就该如此。**测试借漏洞这件事本身，说明乐观偏差在生产场景真实可触。**

一个意图反转：s8 触板用例的 `buy@11` 直单原验证"broker 只拒出界、11.0 可成交"——追板价 11 vs 市价 10 恰是漂移校验治的 stale 单，断言反转为"直单也拒偏离 10%"；guard 的触板拒在更外层不受影响。

## 翻车记档

1. **手算锚基数错**：滑点用例第二笔卖出的 basis 抄了旧数字 1005.01，第一笔实际成交在 10.02 → cost 1007.01，pnl −14.52 非 −12.52——实现对、我的期望错。滑点补丁后所有手算链的**第一环（成交价）先查再抄**。
2. **浮点边界**：`10.1/10 − 1 = 0.010000000000000009 > 0.01` → "恰好 1% 放行"断言红。边界语义别赌浮点，测试改用 0.9% 委托价。

## 诚实边界

- 滑点 0.2% 线性对称是拍的（同回测口径），真实冲击成本与单量/流动性相关——挂机实跑攒对账数据后再看要不要按量分级。
- A 股真实限价单撮合在订单簿（排队/部分成交），纸面模型不建簿——滑点+漂移是"无簿建模"下的诚实近似（文件头注记已更新）。
